## 2. 八个专项核查

| # | 核查项 | 结论 | 行号证据 |
|---|--------|------|----------|
| 1 | `ResolveExpression()` 优先级是否让 `ExpressionDriver` 永久失效 | **满足（不会失效）** | 见下 |
| 2 | `PlayExpression` 期间 body 动作是否真不被打断 | **满足** | 见下 |
| 3 | 101 面饰是否跟 expression 走 | **满足（同参数传递）** | 见下 |
| 4 | 背面动作会不会把正脸贴到背上 | **满足（门控仍在）** | 见下 |
| 5 | 多宠是否真正隔离 | **满足** | 见下 |
| 6 | 离线条带在表情播放时是否异常 | **满足（仅降级，不异常）** | 见下 |
| 7 | `_frameSourcesCache` key 是否含 expression | **满足（另有一处相邻缓存 key 不含）** | 见下 |
| 8 | `SetAppearance()`→`CancelExpression()` 递归/并发 | **满足（无递归；竞态无害）** | 见下 |

**2.1 `ExpressionDriver` 不会永久失效。** 手动态只在「非 default 且未过期」时优先（`PaperdollService.cs:2328-2332`），否则回到 `ExpressionDriver?.GetExpression() ?? default`（L2333）。所有调用方的时长都是有限值：菜单 3000（`PetWindow.Menu.cs:686`）、眨眼 180（L128）、随机 3000（L137）、气泡配对 8000（`PetWindow.axaml.cs:800`）→ `_manualExpireUtc = MaxValue` 的常驻分支（L82）当前无人走到。眨眼 180ms/次，driver 仍有 >95% 的时间可生效。
**附带发现（非本次回归）**：真正的 driver 目前装在**游离实例**上——`App.axaml.cs:147` `new EffectLayerService(..., paperdoll)` 注入的是根容器解析出的另一个 Transient `PaperdollService`（`EffectLayerService.cs:35-38, 79-82`），而 `ApplyPrimaryToEffectLayer`（`App.axaml.cs:296-308`）只绑 `ActionDriver`/`TargetPetId`、未绑 `PaperdollService` → 各宠实例的 `ExpressionDriver` 实际为 null，Hermes 接入前需补绑定。

**2.2 表情不进 AnimService 状态机。** `PlayExpression` 函数体只有两个赋值（`PaperdollService.cs:81-82`）；`PaperdollService.cs` 中 "AnimService" 只出现在注释（L17/22/76/222/295/407/2400），无该类型字段/调用；`MiniPet/Services/AnimService.cs` 中 "Expression" 出现 0 次；菜单点击处理器只调 `PlayExpression`（`PetWindow.Menu.cs:686`），不调 `_animService.Play/SwitchTo`。→ body 动作状态机不可能被表情改动。

**2.3 101 面饰与脸传同一 expression。** `CollectPiecesForFrame` 脸分支 `AddExpressionPieces(..., ResolveFaceAction(root, expression), frame)`（L596）；101 面饰分支 `AddAccessoryPieces(..., expression, ...)`（L606）→ L741 `AddExpressionPieces(..., ResolveFaceAction(root, expression), frame)`。face 与 faceaccessory 各自独立回退（root 不同），正是验收点 3 要的语义。
**注意两条相邻路径**：① `AddAccessoryPieces` 的「动作结构」分支（L723-735）走动作帧、**不读 expression**（01012000 实测只有表情结构，不触发；若将来出现带 `stand1` 的 101 面饰则表情不联动）；② 102 眼饰/103 耳环（L609-615）本就按动作结构走，表情对它们无影响（与 PLAN §2/§3 结论一致）。

**2.4 背面动作门控未被表情绕过。** `IsBodyFaceVisible`（L1909-1922，读 `{body}/{action}/{frame}/face`）→ L564-565 计算 `faceVisible`；脸 L595、101 面饰 L605 在 `!faceVisible` 时 `continue`（部件根本不收集）；`HideFrontFaceLayersOnBackAction`（L1293-1306）+ `FrontFaceLayers`（L1312-1316）在 `RenderFrame:468` 与 `ProbeLayerResolution:273` 照旧执行。表情只改变 face/面饰取哪个表情节点，不新增画脸路径 → 「正脸贴背」不可能被本次改动引入。

**2.5 多宠隔离成立。** `App.axaml.cs:68` `AddTransient<PaperdollService>()` + `App.axaml.cs:88` `AddTransient<PetWindow>()` + `Services/PetManager.cs:317` `ActivatorUtilities.CreateInstance<PetWindow>(_services, cfg)` → 每宠独立实例；状态在实例字段（L53-55、L101-103），`TickExpressionClock` 也是每窗口定时器各调一次（`PetWindow.axaml.cs:295, 1427-1431`）。

**2.6 离线条带不受表情影响。** `BuildOfflineStrips` 固定 `ExpressionDefault` 合成（L2424），产物按 `_currentHash` 缓存键落盘（L224/2406），播放时走 AnimService 图条；表情在离线期间只是「无效」（不改变图条内容），且 `PlayExpression`/`TickExpressionClock` 不碰 WZ、全 try/catch（L79-90、L116-142）→ 无异常路径。属 PLAN §6 R5 已知限制。

**2.7 帧源缓存 key 含 expression；bounds 缓存不含。** `CollectPiecesForFrame` key = `{hash}|{action}|{frame}|{expression}`（L551-552），换表情必换 key、不会取到旧脸 ✅。**但** `GetBounds` 的 key = `{hash}|{action}`（L2037）且逐帧用 `ExpressionDefault` 计算（L2047），`RenderFrame` 用它做画布尺寸（L451/458/496）→ 若某个非默认表情的部件超出「默认表情」联合包围盒，会被画布裁掉。脸部件尺寸通常一致，风险低，但**属未验证项，需实机看图**。

**2.8 无递归；竞态无害。** `CancelExpression` 只赋两个字段（L86-90），不回调 `SetAppearance`、不触发事件 → 无递归。`SetAppearance` 的所有调用点（`PetWindow.axaml.cs:604/1786`、`PetWindow.Menu.cs:470`）与帧循环 `OnTimerTick` 同在 UI 线程（`DispatcherTimer`，`PetWindow.axaml.cs:295`），无真并发；`WarmupFor`/`BuildOfflineStrips` 后台线程只用 `ExpressionDefault` 键，与表情键不交叉。唯一理论竞态：`_manualExpireUtc`（L55）非 volatile（`_manualExpression` 是 volatile，L53），最坏结果是**一帧**读到默认或旧值，不崩、不残留。

## 4. 父 agent 收口清单

**必须改（影响验收点 2/4）**

1. **眨眼时长**：给表情加 per-key 时长（blink ≈180~300ms 单次或限定循环次数），菜单/气泡不要对 blink 用 3000/8000ms。改点：`PetWindow.Menu.cs:686`、`PetWindow.axaml.cs:80-81, 800`；或把时长表放进 `PaperdollService.KnownExpressions`。
2. **随机表情抑制接线**：`PetWindow.axaml.cs:1430` 改为 `SuppressRandomExpression = _walkMode is { IsActive: true } || _isDragging || _agentReflect != AgentState.Idle;`（`_isDragging` 见 L112/L1075/L1103，`_agentReflect` 见 L716/L777）。
3. **随机表情首发时刻**：`RandomExpressionEnabled` 由 false→true 时（或构造时）把 `_nextRandomUtc` 置为 `now + 随机(20~45s)`，避免 `MinValue` 立即触发（`PaperdollService.cs:102, 131-138`）。
4. **开关启动加载**：`Paperdoll` 构造后或 PetWindow 初始化时执行一次 `ApplyExpressionSettings(_configService.GetAutoBlink(), _configService.GetRandomExpression())`（或让 `PaperdollService` 持有 `ConfigService` 初始化），否则 F1 的「重启后开关不生效」会一直在。

**建议改（一致性/未来接入）**

5. 随机池与 `shine`、菜单顺序对齐 PLAN §4.4/§4.3（F5/F6）。
6. `GetBounds` 缓存 key 纳入 expression，或确认所有表情帧与 default 尺寸一致并在文档标注（F7 相邻风险，`PaperdollService.cs:2037/2047`）。
7. 核实非默认表情帧是否带 `map.brow`（F7）；若缺，按 MapleSalon2 加「无 map → 偏移 0 锚 brow」兜底，否则表情可能整片不显示。
8. Hermes/agent 表情驱动接入时，把主宠的 `PaperdollService` 也绑进 `ApplyPrimaryToEffectLayer`（`App.axaml.cs:296-308`），不要继续用 `EffectLayerService` 的游离实例（§2.1）。
9. 若坚持 PLAN §4.4「Run 态手动表情让位」，需在 `ResolveExpression` 增加 agent 忙判定（F8）。
10. 明确开关是「全局」还是「per-pet」；若要 per-pet，应落 `PetInstanceConfig` 而不是 `PetSettings`（F9）。

**无需改（确认符合计划）**

- 菜单仅纸娃娃哨兵模式可见（`PetWindow.Menu.cs:664-666`）；不做 F1~F7 热键（PLAN §4.3 明确不做）。
- 101 面饰联动零额外改动（L606→L741）；背面动作门控保持原样（§2.4）。
- 多宠表情状态隔离成立（§2.5）；离线降级为 default 且不崩（§2.6）。
