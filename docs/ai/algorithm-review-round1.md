## 审查发现的问题清单

### 🔴 P0（必须修，影响算法正确性）

1. **§2.2 柱提取漏斜坡类 tile**：tileset 有 slLU/slRU/slLD/slRD（斜坡），文档柱模型只按「表面 y = min(tiles.y)」处理，斜坡柱表面是**斜线**（左右缘高度不同）。若把斜坡柱当平柱抽，人物脚 y 和视觉都会错。
   **修法**：柱模型加 `slant: (dyLeft, dyRight) | null` 字段；含斜坡块的柱标记为斜坡柱，surfaceY(x) 在柱内线性插值；台阶模板提取时斜坡柱单独成类（天然的平滑过渡素材，比 enV 台阶柱更优雅）。

2. **§2.4 obj 分类阈值与实测分布不符**：实测 60<|dy|≤200 带内有 **119 个 obj（72%）**被「不抄」规则丢弃——射手村大量树/房子装饰在 dy 50~400 带内，按文档规则整张图几乎没装饰可跟路走，路会光秃秃。
   **修法**：三分类改为：站地 |dy|≤60（跟柱）；**装饰带 60<dy≤250 且 obj 在柱正上方 → 也跟柱**（y 锚定改为「柱表面上方 dy 处」，树冠高于地面是正常的）；dy<-200 或水平远离柱 >45px → 后景/不抄。重新实测该规则下站地+装饰 obj ≈ 43+80 ≈ 120+，素材充足。

### 🟡 P1（重要，不阻塞）

3. **§8 BGM 索引懒建耗时低估**：实测全库扫 29.6s（文档写 10s 级）。首次查询会卡近 30s。
   **修法**：分层扫描——先扫 1955 张 town=1 图（~3s，覆盖绝大多数 BGM 命中），未命中再扩全库后台扫；扫描进度在音乐 tab 显示「索引构建中」。

4. **§4.1 柱位图缓存窗口缩放全失效**：缓存键含窗口高，缩放时 128 张全部重建，一次缩放 = 128×(90×H) 渲染，1080p 下瞬时 ~几十 ms×128 卡顿明显。
   **修法**：柱位图按**源分辨率**渲染（固定高，如 900px）+ blit 时缩放绘制；缓存键去掉窗口高，缩放不再失效。

5. **§5 NPC 概率 1/8 与同屏上限的交互**：1/8 概率+8 柱屏 ≈ 同屏期望 1 个，但上限 3 时可能连续 3 柱都中后卡住后续。纯 P2 观感问题，参数化即可（NPC_P 改 1/10，或加冷却柱数）。

6. **需求 F18-16 淡入淡出没有覆盖「首次进入模式3」时序**：文档 §6 只写了换歌 crossfade，首次进入（无旧路可淡出）应只做新背景 opacity 0→1，文档未明说。补一句。

### 🟢 P2（建议）

7. tex=1x1 问题：探针 ExtractPng 对 tile 路径返回 1x1 占位（探针环境没走 tileset 解码路径），实现时用项目 SpriteService 正常解码——非算法问题，提示 Claude Code 别被探针的 1x1 误导。
